# Recipe: Godot and Ziva

Working in the Godot 4.7 project, through the editor or the Ziva MCP tools. How a screen is built is in `screens-flow.md`.

## Gotchas
- **Ziva needs a sign-in to see the game** (2026-11-13, M0): `run_scene` ran the game but failed at the screenshot, and `get_screenshot` and `view_image` failed outright with "Not signed in". When you see that, ask Mike or Mark to sign in to Ziva in the Godot dock; the free Hobby plan is enough.
- **Ziva won't run a game someone is playing** (2026-11-13, M1): `run_scene` refuses while the scene is already running in the editor, because starting it would close their game. When that happens, ask the person to stop their game, then run it.
- **Ziva's test runner has no GUT** (2026-11-13, M0): tests extending `GutTest` fail to parse, and tests extending `RefCounted` aren't found. When writing tests for `run_tests`, extend `Node` and name each test function `test_...`.
- **Edited images keep their old import** (2026-11-13, M1): an image overwritten from a script still showed its old version in game, because the editor hadn't reimported it. When you change an image file outside the editor, rename it (Ziva's `mv`) or have someone click into the Godot window so it reimports. Quicker, and it also works for new images pulled from git (2026-11-13, M4): `C:/Games/Godot/Godot_v4.7.2-stable_win64_console.exe --headless --path . --import` imported ten new sheets and later reimported 20 changed ones, with no one at the editor. Compare `source_md5` in `.godot/imported/*.md5` with the file to check.
- **A folder won't delete if a shell is inside it** (2026-11-13, M0): Ziva's `rm` deleted the files but failed on the folder while a terminal's working directory was inside it. When deleting a folder, make sure no shell is sitting in it.
- **Ziva's `create_file` never overwrites** (2026-11-13, M0): it refuses if the file exists. When changing an existing file, use `edit_file`, or write the file directly from the shell.
- **`execute_script` needs types on loop variables over literal lists** (2026-11-13, M1): `for ox in [-8, 0, 8]` then `var bx := 500 + ox` fails to parse ("Cannot infer the type"). When looping over a literal list, write `for ox: int in [...]`.
- **Win: Python has PIL and numpy, not scipy** (2026-11-19, M4): `C:/Python313/python` had PIL 12.3 and numpy 2.5 and did all the marsh mask work; `import scipy` failed. When measuring or editing images, either Python or Godot's `Image` (`Image.load_from_file`, `get_used_rect`, `save_png`, from `execute_script`) works; use Godot's when you need to read project files the way the game sees them.
- **Win: print logs prove behaviour without screenshots** (2026-11-13, M0): printing Pip's position and scale during a `run_scene` with injected inputs showed he walked and shrank, even when the screenshot failed. When checking movement or numbers, print them and read the run's output. To print without touching game code (2026-11-13, M4): a throwaway probe scene in `tools/_probe/` that instances the screen and prints Pip's `gait`, `sprite.animation` and `modulate` every frame proved each gait played its own loop with no flash. Run the probe scene with `run_scene`, then delete it.
- **Ziva loads only in a session that starts inside the repo** (2026-11-13, M2): a session opened in the `Pip FF7` workspace folder got only Ziva's `start_godot`, which failed with "No project.godot found". Switching the folder mid-chat didn't reload it. When Ziva's tools are missing, start a new session inside `Pip-ff7/` rather than retrying.
- **Win: Godot runs image scripts without Ziva** (2026-11-13, M2): a script extending `SceneTree`, run with `C:/Games/Godot/Godot_v4.7.2-stable_win64_console.exe --headless -s <script>.gd`, measured every sprite frame with `Image.get_used_rect`. When Ziva isn't connected and you need image numbers, write the script in the scratchpad and run it this way.
- **Win: a headless run catches load errors, but gives no screenshot** (2026-11-13, M2): `--headless --path . --quit-after 120 res://scenes/screens/marsh.tscn` ran the scene and reported no errors. When Ziva is down, use it to check that a scene still loads. It doesn't count as "done" for anything that has to be seen.
- **`run_scene` presses actions at full strength** (2026-11-13, M3): creeping from a gentle push of the stick couldn't be tested, because injected actions have no strength setting. When something depends on how far the stick is pushed, test the keyboard route with `run_scene` and hand the analogue part to Mike or Mark on the pad.
- **Short test walks hit the walk-area edge** (2026-11-13, M3): from Pip's start on the marsh, moving right, up or left reached the edge in under half a second. That made running look broken, when he was only standing against the edge. When comparing speeds, walk along the path (right and up together on the marsh), and print his position to check he's still moving.
- **`get_input_map` doesn't always say "Physical"** (2026-11-13, M3): a Shift key saved with `physical_keycode` was listed as plain "Shift". When you need to know whether a key is physical, read the action's `project.godot` diff.
- **`run_scene` takes its screenshot as the inputs end** (2026-11-13, M4): the "mid-run" screenshot showed Pip standing, because the capture happened on the frame the move key was released and he had already gone back to idle. When you need a screenshot mid-movement, try a throwaway probe scene that pauses the tree a set number of frames into the gait. Give the probe `process_mode = 3` (always) and the instanced screen `process_mode = 1` (pausable), so the pose holds still until the capture.
- **An editor save can drop a scene's video clip** (2026-11-20, M4): after the scenes were saved from the editor, `marsh.tscn` had lost `clip = ExtResource(...)` on `Loop`, so the painting stayed hidden and only the Occ_ shapes drew. Most likely the editor was holding an older copy of the scene. When a screen goes black apart from its shapes after an editor save, `git diff` the scene for dropped lines, put them back, then `open_scene` it.
- **A probe that places Pip inside an exit changes screen** (2026-11-20, M4): placing Pip at (1375, 1062) on the stream fell inside the bottom exit and loaded the boardwalk. When placing Pip with a probe, keep him clear of `Exits` polygons.
- **Win: an autopilot walks Pip through every screen in one run** (2026-11-20, M4): a throwaway script added a node to `get_tree().root` (so it survived scene changes), pressed `move_*` with `Input.action_press` toward waypoints, and saved a screenshot after each arrival. It walked marsh → boardwalk → stream and back through the real exits. When checking a chain of screens, try this rather than timed `run_scene` inputs.
- **A long `run_scene` times out but still runs** (2026-11-20, M4): a 90 s `run_scene` returned "Request timed out", but the game finished and its prints were all in `get_godot_errors`. When a run is longer than about a minute, expect the timeout and read the output and saved screenshots afterwards.
