# Recipe: layering a screen in Affinity

The person draws the cut-outs in Affinity; an agent brings them into the game each time they press a button. It replaces cutting by script for anything the person can select faster than a tool can (see "Cut-outs" in `screens-flow.md`). Agents run it with the `/layering` skill.

## How it works
1. **Open.** The agent copies `assets/screens/<screen>/<screen>_bg.jpg` into `Desktop/PipFF7_layering/` (Affinity scripts can only read the Desktop), opens it there at its real 1920x1080 and saves it as `<screen>.afdesign`. The document name is the screen name: `marsh`, `boardwalk`, `stream`.
2. **Layer.** The person makes pixel layers above the painting (select, duplicate to a new layer).
3. **Send.** They say "sent <screen>" in chat, and the agent runs the send code (`tools/affinity/send_to_game.js`, with `Application.alert` swapped for `console.log`) on that open document through `execute_script` (DECISIONS, 2026-11-20). It writes each layer, cropped, next to the document and touches `<screen>__READY`. Running the library script **Pip FF7 - Send layers v3** from the Scripts panel does the same, but it has silently done nothing on Mike's PC, so it's the fallback.
4. **Receive.** The agent runs `tools/send_layers.sh <screen>`. That writes `assets/screens/<screen>/<screen>_occ_<name>.png`, rewrites the `Occ_<name>` sprites in `scenes/screens/<screen>.tscn`, and imports. The agent then runs the screen and looks.

Sending again replaces every `Occ_` sprite and PNG, so the person can iterate. Nothing else in the scene is touched.

The `.afdesign` documents are the only source for a screen's shapes. After a layering run, save them in Affinity and copy them to `kept-assets/screen-layers/` (outside git); to re-layer a screen, open that copy rather than starting from the painting. The `Desktop/PipFF7_layering/` folder is only a work folder.

## Which screens are done
A screen counts as layered when its scene's `Overhead` node carries `metadata/layered = true`. `tools/layers_to_game.gd` sets it on every send, and an empty send (no layers above the painting) is how a person says "I looked, this screen needs none". `bash tools/layering_status.sh` lists each screen as `TODO` or `DONE`. There is no other record: the plan and who's doing it live on the board, and a screen that has no scene yet doesn't appear until someone builds it. Sending again is always allowed (a new walk area or a repaint makes the stamp stale), and a layer that existed before and is no longer sent is removed along with its PNG.

To do several or all of the screens in one go, use `/layering all`. It opens every `TODO` painting in Affinity at once; the watcher handles all of them.

## Front or behind: the bottom-edge rule
- The bottom layer is the painting and is never sent.
- Every visible layer above it is cut into its separate shapes, and **each shape covers Pip only while his feet are above its bottom edge** at his x (`scripts/occluder.gd`). So he walks behind a bank from above and in front of it from below. A shape whose bottom edge is the bottom of the screen always covers him. The edge is read from the shape's own pixels: nothing to set by hand, and a slanted edge works.
- **Name a layer "Over..."** (any case) for things that hang, like willow fronds or branches: their bottom edge is in mid-air, so the rule would let Pip walk in front of them. An "Over" layer always covers him and isn't split.
- **Still or animated, it's the same.** On a screen with a `Loop` node (`screens-flow.md`, "An animated screen") each shape draws the `Loop`'s pixels (video or shader motion, `screens-shader-motion.md`) through itself, so it moves with it; on a still screen it draws the painting's pixels.
- Specks under 64 pixels are dropped (the receive step says how many).
- Hidden layers and non-pixel layers (groups, shapes) are skipped and reported. Rasterise a shape first.
- Sprites are named `Occ_layer<N>`, or `Occ_layer<N>_<k>` when the layer has several shapes, N being the layer's position above the painting, so a layer keeps its name between sends. (`layers_to_game.gd` can still place a `WORLD` layer with a fixed ground line if a manifest asks for one; the Affinity script doesn't send any.)

## Depth occlusion (M5)
A screen can hide Pip by depth instead of drawn shapes: anything nearer than the ground at his feet covers him. The stream and boardwalk use depth plus automatic post shapes (`Auto_` sprites, step 5): depth barely tells the boardwalk's right-hand post from the planks behind it (at most 0.03 nearer), so Pip flickered between in front and behind. The boardwalk's Affinity posts shape `Occ_layer2` stays in its scene, switched off (`process_mode = 4`, `visible = false`); delete those two lines to bring it back. The marsh uses depth plus automatic bank shapes (SAM 3, step 5), because the banks along its path are too low for the depth model to tell from the path (depth covered 0% and 19% of what they cover) (DECISIONS, 2026-11-20, 2026-11-22 and 2026-11-24). The stream also has SAM 3 reed shapes. All three depth maps are Depth Anything V2 Large on the whole painting, made on ComfyUI (step 1). Its Affinity bank shapes `Occ_layer1_1` and `Occ_layer1_2` stay in the scene, switched off the same way. Each scene's `DepthOcc` node under `Overhead` does it. A send from Affinity still writes `Occ_` sprites beside it, so a screen can take a drawn shape wherever depth fails.
The `/occlusion <screen>` skill (`.claude/skills/occlusion/`) runs steps 1, 5, 6 and the probe for a screen, and proposes its walk area (`tools/depth/walk_guess.py`, from SAM 3's "dirt path" / "wooden boardwalk" / "footbridge" masks); the person adjusts the walk area and judges the probe sheet (`tools/depth/probe_sheet.py`).
1. **Depth map and masks, on ComfyUI** (MimicPC, Mike's saved template; hosted GPU). `tools/depth/comfy_queue.js`, run in the ComfyUI page, uploads the painting and queues Depth Anything V2 Large (`DownloadAndLoadDepthAnythingV2Model`, `depth_anything_v2_vitl_fp16`) on the whole painting, and SAM 3 (`TBGSAM3ModelLoaderAdvanced` "local", `TBGSam3Segmentation`, confidence 0.3, `min_size` 1, saving output 5 `combined_mask`) once per thing that should hide Pip ("wooden post", "reeds", "grassy bank") and per walkable surface. Download the outputs (storage panel: select all, ⋮ → Download → Zip File; Chrome saves to `../preprocessing/_inbox`), then `tools/depth/comfy_import.py <zip> <screen>` puts them in `tools/depth/comfy/<screen>/` and the depth map, in the game's 16-bit red/green format (8-bit grey v becomes red v, green v), at `assets/screens/<screen>/<screen>_depth.png`. Nearer is whiter. The nodes on the template: `comfyui_segment_anything`, kijai `ComfyUI-DepthAnythingV2`, Ltamann `ComfyUI-TBG-SAM3` and `ComfyUI-DepthAnythingV3-TBG`, spacepxl `ComfyUI-Depth-Pro`, lldacing `ComfyUI_BiRefNet_ll`. Offline fallback, tiled Depth Anything V2 Small (worse: 92.7% / 0.92% on the boardwalk posts against 95.9% / 0.33%): `../segment-env/venv/Scripts/python.exe tools/depth/depth.py assets/screens/<screen>/<screen>_bg.jpg ../segment-env/out/depth/<screen>.png` (same environment and `HF_HOME` as `screens-shader-motion.md`).
2. **Into the game.** Import, then add a `Sprite2D` under `Overhead` with `scripts/depth_occluder.gd`; it uses the screen root's `depth_map` (set for Pip's shadow, `screens-flow.md`) unless given its own. It draws over Pip only inside his box and above his feet, so ground in front of him never hides him. On a shader-motion screen the swaying pieces carry their depth (a hidden viewport sways the depth map with the same shaders).
3. **Gaps.** Where Pip can step over a hole in what he walks on (the boardwalk's missing plank), draw it as a `Polygon2D` under a `Gaps` node on the screen. The ground at his feet is never read inside it but filled in from the walk surface behind and in front, so the planks round the hole don't hide him. The node is hidden in the game.
4. **Tune** on the node: `tolerance` (0.01: how much nearer something must be), `grow` (3 px past an edge, since the depth map's edges run small), `show_mask` (tints what covers him red).
5. **Automatic shapes** for what depth misses. `../segment-env/venv/Scripts/python.exe tools/depth/auto_occ.py <screen> --scene` (same environment; about a minute) finds posts by words with Grounding DINO and SAM 2.1, writes them to `assets/screens/<screen>/auto/`, and replaces every `Auto_` sprite under `Overhead` (on the bottom-edge rule, `scripts/occluder.gd`). It leaves `Occ_` sprites from Affinity alone, and an Affinity send leaves `Auto_` alone. Look at `../segment-env/out/auto/<screen>/overlay.jpg` (posts yellow, banks red), then import (`godot --headless --path . --import`).
   **From SAM 3 masks** (step 1): `../segment-env/venv/Scripts/python.exe tools/depth/mask_shapes.py <screen> <thing> tools/depth/comfy/<screen>/<screen>_sam3_<thing>_mask.png` adds each piece as an `Auto_<thing>_<k>` sprite beside the existing `Auto_` sprites (rerunning replaces that thing only). For low banks add `--banks`: `tools/depth/cut_banks.py` first cuts the mask at the walk area (bank with path below it is behind that path, bank with none is in front, a lip inside the walk area counts only on camera-facing edges), since SAM 3 merges a bank with whatever lies below it. Before cutting, the bank mask grows up to 12 px into dark ink, to take in the bank's outline. Add `--clear` to remove the other `Auto_` sprites (as done for the marsh's Illustrator's Depth banks). Raised bank SAM 3 misses: the person paints it red on the bank overlay, `tools/depth/hand_mask.py` turns that into a mask, and `--raised=<mask>` adds it, counting inside the walk area too (the marsh's mossy bank by the bend). Look at `../segment-env/out/auto/<screen>/<thing>_overlay.jpg`, then import.
   **Low banks, older route** (`--banks` on `auto_occ.py`; non-commercial licence; replaced on the marsh 2026-11-24): first run `../illustrators-env/venv/Scripts/python.exe tools/depth/layers.py <screen>` (Illustrator's Depth, about 2 min), which writes the painting's layer order to `../illustrators-env/out/<screen>.npy`. Near each walk-area edge that faces the camera, whatever is on a higher layer than the path just inside it becomes a bank shape, covering Pip only while his feet are above that edge (its `edge` line in `scripts/occluder.gd`).
   Setup of `../illustrators-env`, once: clone `https://github.com/nissmar/illustrators_depth` (with `--recursive`) to `../illustrators-env/src`; get the weights from the Google Drive link in its README and unzip them to `../illustrators-env/checkpoints/` (2.4 GB); `uv venv --python 3.12 ../illustrators-env/venv`; then install `torch==2.8.0 torchvision==0.23.0` from `https://download.pytorch.org/whl/cu126`, the repo's requirements except `open3d`, `gradio`, `cairosvg`, `datasets`, `tensorboard`, `diffusers`, `vtracer`, `potracer`, and `-e src/ml-depth-pro --no-deps`. About 8 GB in all. The model is under Adobe's non-commercial research licence.
6. **Score before running the game.** `tools/depth/score.py` says how much of each Affinity shape over Pip a depth map, plus any automatic shapes (`SCENE=scenes/screens/<screen>.tscn`), covers, and how much of Pip it hides wrongly (its docstring says how to run it against shapes that have since been removed). A new screen has no Affinity shapes, so there it's the probe sheet (`tools/depth/probe_sheet.py`) and the person's walk.

Gotchas
- MimicPC and ComfyUI themselves (node packs, disk, gated weights, logs, Manager): `comfyui.md`.
- **One whole-painting run can't tell a post from its bridge** (2026-11-20): Depth Anything at 1036 px made the stream's posts only 0.002 nearer than Pip's feet, so they covered 4% and 39% of what Affinity covers. Six zoomed tiles fitted to the whole run took them to 99% and 98%. When something thin at mid-distance doesn't hide Pip, look at the tiling before the tolerance.
- **The ground under Pip must come from the walk area** (2026-11-20): reading it at points along his feet took the post he stood behind as his ground, so it could never hide him; the lowest reading took water seen between planks and hid him behind the bridge. `depth_occluder.gd` takes the middle of the points inside the walk area.
- **Large on the whole painting beat Small with tiles** (2026-11-24, M5): an earlier round (2026-11-20) found Base and Large *with tiles* no better than Small. Depth Anything V2 Large on the whole painting, untiled, on ComfyUI, covered the boardwalk posts 95.9% against 92.7% and hid Pip wrongly a third as often (0.33% against 0.92%), even saved at 8 bits. It still missed the stream's reeds (62%), which SAM 3 "reeds" shapes bring to 91.5%. Its weights are non-commercial (CC BY-NC); the project is private. When a depth map hides Pip in odd places, try the untiled Large run before tuning.
- **SAM 3's `min_size` drops thin things** (2026-11-24, M5): at its default 100 it found four boardwalk posts and kept none. Set it to 1.
- **Grounding DINO merges every match into one mask** (2026-11-24, M5): on ComfyUI, "wooden post" with Grounding DINO + SAM-HQ masked the whole boardwalk, and as a shape it hid Pip wrongly 6 to 15% of the time. SAM 3 with the same words found each post on its own. When a text prompt grabs the thing's surroundings, try SAM 3 before tuning thresholds.
- **A gap in the planks hid Pip behind the bridge he stood on** (2026-11-22, M5): over the boardwalk's missing plank, every walk-area point at his feet read the water below (nearness 0.31), so the planks round him (0.36 to 0.45) hid all but his ears. The gap crosses the whole bridge, so it can't come out of the walk area. `depth_occluder.gd` now lifts the ground to the nearest walk-area row behind his feet (within 80 frame px) when the ground in front is nearer still, which leaves ordinary ground alone. That rule alone still hid his legs along the gap's slanted edges (row medians across his width mixed plank and water), and loosening it (nearest point, or narrower rows) cost the stream's posts up to 80 points; the fix was marking the gap (step 3). When Pip vanishes into something he's standing on, look for a gap under his feet and mark it, rather than changing the tolerance.
- **Don't make a post solid to hide a depth failure** (2026-11-22, M5): a post at the boardwalk's edge flipped Pip from in front to behind as he walked up past it. Carving it out of the walk area stopped the flip, but Mike rejected it: the bridge is straight and Pip should walk behind the post. The post read at most 0.03 nearer than the planks round it, too little for depth. When depth can't separate a thing from what's behind it, keep its Affinity shape (bottom-edge rule) instead of changing where Pip walks.
- **Win: score depth maps before running the game** (2026-11-20, M5): measuring how much of each Affinity shape over Pip a depth map would cover (in Python, against the shapes' PNGs) compared seven model and setting combinations in minutes, without opening Godot. When trying another depth model or setting, try scoring it against the Affinity shapes first.
- **Depth Pro was worse than tiled Depth Anything** (2026-11-22, M5): `apple/DepthPro-hf` (fp16, about 2 min a screen) covered the boardwalk post 51% at best against 93%, and the marsh banks no better. Its raw `predicted_depth` is already inverse depth, so inverting it again makes the sky nearest. When trying another depth model, check the preview's sky is dark before scoring.
- **Win: posts by words beat every depth model** (2026-11-22, M5): "wooden post." with `max_box` 0.02 found all four posts on the boardwalk and the stream (a larger box swallowed the whole stream bridge). Depth plus those shapes covered the posts 95 to 100%, and in the game the boardwalk post stayed in front of Pip all the way up past it, where depth alone dropped it. When something thin and nameable doesn't hide Pip, try `auto_occ.py` before drawing it.
- **Low banks: layer order beat depth and SAM** (2026-11-22, M5): text prompts never found the marsh's low banks, and SAM points along the walk edge covered only 54% of what the Affinity banks cover. Illustrator's Depth, read as "a higher layer than the path just inside this edge", covered 78% and in the game cut Pip's legs at the bank's lip much as the Affinity shapes do. On its own it can't stand in for the depth map (it hid Pip wrongly 9 to 24% of the time): the path is one layer from the horizon to the camera, so everything behind Pip ranks above it. A bank's lip lies inside the walk area (16% of the marsh's bank pixels), so a shape clipped at the walk edge does nothing, and a shape's own lowest pixels as its bottom hid Pip completely by a bend; hence the `edge` line. Beside bridges the same rule takes flat ground at the edge and hides Pip's feet. When a screen has low banks along its path, try `--banks` before drawing them.

## Gotchas
- **Affinity's script library can't overwrite or delete** (2026-11-14): saving a script under an existing title fails, and there's no delete tool. When the send script changes, save it under a new title (the current one is "v3"; update the references here and in the skill), and ask the person to delete the old one so they don't run it by mistake.
- **Affinity can only read and write the Desktop** (2026-11-14): `Document.load` of a path in the repo returns PERMISSION_DENIED. When a screen has to be opened, copy the painting to the work folder first.
- **Affinity can't tell you when the user saves, and a script ends when it returns** (2026-11-14): there is no save event and no timer outlives the call. When something must happen on the user's action, have a script write a file and watch for it from outside (the `READY` file, with Monitor).
- **`PixelBuffer.create` is not zeroed** (2026-11-14): layers built from it carried leftover pixels from earlier buffers. When writing a transparent layer from a script, `fill(0)` the array first.
- **`children.all` is recursive, `children` is not** (2026-11-14): listing a clipped shape showed its painting copy twice, and deleting the "stray" one removed the clip. When listing a spread's layers, iterate `spread.children`.
- **Exporting a selection doesn't isolate it** (2026-11-14): `doc.export` with a selection area included the layers beneath. When you need one layer's pixels, read them with `node.createCompatibleBuffer(true)`, which is laid out in canvas coordinates.
- **Slicing one cut-out into horizontal bands gave a straight cut across Pip** (2026-11-14): each band had its own ground line, and where Pip's feet fell between two lines the upper band stopped covering him along a dead-straight edge. When a cut-out looks wrong at a boundary, keep it as one piece, and judge the overlap.
- **The editor keeps its own copy of the scene** (2026-11-14): after `send_layers.sh` rewrote `marsh.tscn`, Ziva's `get_godot_errors` said the scene "changed on disk" and refused until `open_scene` reloaded it. `run_scene` still ran the new file. If a Ziva scene tool complains, `open_scene` the file, then carry on.
- **A document that isn't 1920x1080 still works** (2026-11-14): `layers_to_game.gd` scales the layer's mask to game size and takes the colours from the painting, so it stays sharp. Better to work at full size.
- **Check what Pip can actually reach before cutting** (2026-11-14): most of a screen's foreground is outside his walk area, and cut-outs there never hide him. Draw the walk area over the painting with Pip's body drawn at every foot position (height from `far_height`/`near_height`), and cut only what falls inside.
- **Look at the open document before asking the person to mark** (2026-11-19, M4): the brief said `marsh.afdesign` held only the painting, but the open copy had an unsaved bank layer and a hidden painting. When starting a layering pass, list the layers with `execute_script` and `render_spread` before saying what to draw.
- **A send can be tested without the person** (2026-11-19, M4): running the send script's code through `execute_script`, with `Application.alert` swapped for `console.log`, sent the marsh exactly as the button would. When checking a pipeline change end to end, try that, but only on a screen whose layers are the person's real ones, since it marks the screen as layered.
- **Place Pip exactly with a probe scene rather than walking him there** (2026-11-19, M4): five timed walks with `run_scene` never reached the spot behind the far bank, because the walk area stopped him. When checking whether a shape covers Pip at a given point, a throwaway scene in `tools/_probe/` that sets his `position` and prints each `Occ_` sprite's `visible` answered it in one run. Delete the probe afterwards.
- **The Scripts panel send can do nothing** (2026-11-20, M4): Mike ran "Send layers v3" three times and got no message and no files, although the library copy matched `tools/affinity/send_to_game.js`. When the person says they've sent and no `<screen>__READY` turns up, read their open document with `execute_script` and run the send code on it from chat (`Application.alert` swapped for `console.log`). That sent boardwalk and stream every time.
- **Things standing in water need "Over"** (2026-11-20, M4): the bridge posts' bottom edges are in the water, below the planks Pip walks on, so the bottom-edge rule let him stand in front of them. When something rises from below the walking surface (posts, piles), put it on an "Over" layer.
- **An "Over" shape is only right if Pip can't get in front of it** (2026-11-20, M4): the stream's mushrooms, on "Over", drew over Pip's belly where the walk area let him stand below them. When a shape should always cover Pip's feet, narrow the walk area so he can't reach the ground in front of it, rather than taking it off "Over".
- **Affinity's desktop path is `Application.userDesktopPath`** (2026-11-20, M4): `getUserDesktopPath` from `/application.js` isn't a function, and the `Application.getUserDesktopPath` getter is deprecated. When a script needs the Desktop, use `const { Application } = require('/application.js'); Application.userDesktopPath`.
