# Recipe: layering a screen in Affinity

The person draws the cut-outs in Affinity; an agent brings them into the game each time they press a button. It replaces cutting by script for anything the person can select faster than a tool can (see "Cut-outs" in `screens-flow.md`). Agents run it with the `/layering` skill.

## How it works
1. **Open.** The agent copies `assets/screens/<screen>/<screen>_bg.jpg` into `Desktop/PipFF7_layering/` (Affinity scripts can only read the Desktop), opens it there at its real 1920x1080 and saves it as `<screen>.afdesign`. The document name is the screen name: `marsh`, `boardwalk`, `stream`.
2. **Layer.** The person makes pixel layers above the painting (select, duplicate to a new layer).
3. **Send.** They say "sent <screen>" in chat, and the agent runs the send code (`tools/affinity/send_to_game.js`, with `Application.alert` swapped for `console.log`) on that open document through `execute_script` (DECISIONS, 2026-11-20). It writes each layer, cropped, next to the document and touches `<screen>__READY`. Running the library script **Pip FF7 - Send layers v3** from the Scripts panel does the same, but it has silently done nothing on Mike's PC, so it's the fallback.
4. **Receive.** The agent runs `tools/send_layers.sh <screen>`. That writes `assets/screens/<screen>/<screen>_occ_<name>.png`, rewrites the `Occ_<name>` sprites in `scenes/screens/<screen>.tscn`, and imports. The agent then runs the screen and looks.

Sending again replaces every `Occ_` sprite and PNG, so the person can iterate. Nothing else in the scene is touched.

The `.afdesign` documents are the only source for a screen's shapes. After a layering run, save them in Affinity and copy them to `kept-assets/screen-layers/` (outside git); to re-layer a screen, open that copy rather than starting from the painting. The `Desktop/PipFF7_layering/` folder is only a work folder.

## Which screens are done
A screen counts as layered when its scene's `Overhead` node carries `metadata/layered = true`. `tools/layers_to_game.gd` sets it on every send, and an empty send (no layers above the painting) is how a person says "I looked, this screen needs none". `bash tools/layering_status.sh` lists each screen as `TODO` or `DONE`. There is no other record: the plan and who's doing it live on the board, and a screen that has no scene yet doesn't appear until someone builds it. Sending again is always allowed (a new walk area or a repaint makes the stamp stale), and a layer that existed before and is no longer sent is removed along with its PNG.

To do several or all of the screens in one go, use `/layering all`. It opens every `TODO` painting in Affinity at once; the watcher handles all of them.

## Front or behind: the bottom-edge rule
- The bottom layer is the painting and is never sent.
- Every visible layer above it is cut into its separate shapes, and **each shape covers Pip only while his feet are above its bottom edge** at his x (`scripts/occluder.gd`). So he walks behind a bank from above and in front of it from below. A shape whose bottom edge is the bottom of the screen always covers him. The edge is read from the shape's own pixels: nothing to set by hand, and a slanted edge works.
- **Name a layer "Over..."** (any case) for things that hang, like willow fronds or branches: their bottom edge is in mid-air, so the rule would let Pip walk in front of them. An "Over" layer always covers him and isn't split.
- **Still or animated, it's the same.** On a screen with a `Loop` node (`screens-flow.md`, "An animated screen") each shape draws the video's pixels through itself, so it moves with the loop; on a still screen it draws the painting's pixels.
- Specks under 64 pixels are dropped (the receive step says how many).
- Hidden layers and non-pixel layers (groups, shapes) are skipped and reported. Rasterise a shape first.
- Sprites are named `Occ_layer<N>`, or `Occ_layer<N>_<k>` when the layer has several shapes, N being the layer's position above the painting, so a layer keeps its name between sends. (`layers_to_game.gd` can still place a `WORLD` layer with a fixed ground line if a manifest asks for one; the Affinity script doesn't send any.)

## Gotchas
- **Affinity's script library can't overwrite or delete** (2026-11-14): saving a script under an existing title fails, and there's no delete tool. When the send script changes, save it under a new title (the current one is "v3"; update the references here and in the skill), and ask the person to delete the old one so they don't run it by mistake.
- **Affinity can only read and write the Desktop** (2026-11-14): `Document.load` of a path in the repo returns PERMISSION_DENIED. When a screen has to be opened, copy the painting to the work folder first.
- **Affinity can't tell you when the user saves, and a script ends when it returns** (2026-11-14): there is no save event and no timer outlives the call. When something must happen on the user's action, have a script write a file and watch for it from outside (the `READY` file, with Monitor).
- **`PixelBuffer.create` is not zeroed** (2026-11-14): layers built from it carried leftover pixels from earlier buffers. When writing a transparent layer from a script, `fill(0)` the array first.
- **`children.all` is recursive, `children` is not** (2026-11-14): listing a clipped shape showed its painting copy twice, and deleting the "stray" one removed the clip. When listing a spread's layers, iterate `spread.children`.
- **Exporting a selection doesn't isolate it** (2026-11-14): `doc.export` with a selection area included the layers beneath. When you need one layer's pixels, read them with `node.createCompatibleBuffer(true)`, which is laid out in canvas coordinates.
- **Slicing one cut-out into horizontal bands gave a straight cut across Pip** (2026-11-14): each band had its own ground line, and where Pip's feet fell between two lines the upper band stopped covering him along a dead-straight edge. When a cut-out looks wrong at a boundary, keep it as one piece, and judge the overlap.
- **The editor keeps its own copy of the scene** (2026-11-14): after `send_layers.sh` rewrote `marsh.tscn`, Ziva's `get_godot_errors` said the scene "changed on disk" and refused until `open_scene` reloaded it. `run_scene` still ran the new file. If a Ziva scene tool complains, `open_scene` the file, then carry on.
- **A document that isn't 1920x1080 still works** (2026-11-14): `layers_to_game.gd` scales the layer's mask to game size and takes the colours from the painting, so it stays sharp. Better to work at full size.
- **Check what Pip can actually reach before cutting** (2026-11-14): most of a screen's foreground is outside his walk area, and cut-outs there never hide him. Draw the walk area over the painting with Pip's body drawn at every foot position (height from `far_height`/`near_height`), and cut only what falls inside.
- **Look at the open document before asking the person to mark** (2026-11-19, M4): the brief said `marsh.afdesign` held only the painting, but the open copy had an unsaved bank layer and a hidden painting. When starting a layering pass, list the layers with `execute_script` and `render_spread` before saying what to draw.
- **A send can be tested without the person** (2026-11-19, M4): running the send script's code through `execute_script`, with `Application.alert` swapped for `console.log`, sent the marsh exactly as the button would. When checking a pipeline change end to end, try that, but only on a screen whose layers are the person's real ones, since it marks the screen as layered.
- **Place Pip exactly with a probe scene rather than walking him there** (2026-11-19, M4): five timed walks with `run_scene` never reached the spot behind the far bank, because the walk area stopped him. When checking whether a shape covers Pip at a given point, a throwaway scene in `tools/_probe/` that sets his `position` and prints each `Occ_` sprite's `visible` answered it in one run. Delete the probe afterwards.
- **The Scripts panel send can do nothing** (2026-11-20, M4): Mike ran "Send layers v3" three times and got no message and no files, although the library copy matched `tools/affinity/send_to_game.js`. When the person says they've sent and no `<screen>__READY` turns up, read their open document with `execute_script` and run the send code on it from chat (`Application.alert` swapped for `console.log`). That sent boardwalk and stream every time.
- **Things standing in water need "Over"** (2026-11-20, M4): the bridge posts' bottom edges are in the water, below the planks Pip walks on, so the bottom-edge rule let him stand in front of them. When something rises from below the walking surface (posts, piles), put it on an "Over" layer.
- **An "Over" shape is only right if Pip can't get in front of it** (2026-11-20, M4): the stream's mushrooms, on "Over", drew over Pip's belly where the walk area let him stand below them. When a shape should always cover Pip's feet, narrow the walk area so he can't reach the ground in front of it, rather than taking it off "Over".
- **Affinity's desktop path is `Application.userDesktopPath`** (2026-11-20, M4): `getUserDesktopPath` from `/application.js` isn't a function, and the `Application.getUserDesktopPath` getter is deprecated. When a script needs the Desktop, use `const { Application } = require('/application.js'); Application.userDesktopPath`.
